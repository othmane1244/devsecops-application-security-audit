## Journaux diagnostiques, parsing, bundle de règles et limites

- Le JSON du worktree n’a pas de tableau `Results`; l’inventaire du worktree n’avait trouvé aucun Dockerfile, Terraform ou Kubernetes candidat. Conclusion : **aucun fichier pris en charge**, et non « aucun risque ».
- Pour l’arbre Juice Shop, le JSON contient des résultats associés à six fichiers avec constats : `infrastructure/Dockerfile`, `infrastructure/terraform/main.tf`, `infrastructure/terraform/networking.tf` et les trois exemples Terraform. Il contient aussi deux entrées de répertoire sans constat. Le journal diagnostique cite également `infrastructure/terraform/variables.tf` et `outputs.tf` pendant le parsing; ils n’ont pas de cible avec résultat dans le JSON. Le rapport ne livre pas une liste exhaustive des fichiers analysés sans constat.
- Les commandes principales utilisaient `--quiet`, qui a produit des journaux vides. Dans le journal `--debug`, 46 lignes contiennent des termes de parsing et les huit fichiers Terraform/Dockerfile attendus apparaissent dans les traces. Aucune ligne d’erreur de parsing, de syntaxe ou de type « failed to parse » n’a été repérée; aucun message de parsing n’est au niveau ERROR/WARN. Cela établit une activité de parsing visible, pas la réussite exhaustive de toutes les unités ni l’absence d’erreurs silencieuses.
- Le journal diagnostique montre une tentative de consultation du cache de checks qui échoue, puis le message `Falling back to embedded checks`. C’est l’unique erreur Trivy relevée et elle explique le choix du bundle de repli. Elle peut expliquer le code de sortie 1, mais le journal ne relie pas explicitement ces événements; l’erreur sous-jacente du cache n’est pas reproduite ici. La cause précise du code non nul reste donc inconnue, et un JSON valide n’est pas une preuve de contrôle complet.
- Les deux fichiers Compose ne sont pas couverts par les scanners déclarés. La version examinée ne fournit pas de scanner de configuration GitHub Actions; aucun workflow n’a d’ailleurs été trouvé dans l’image. Les fichiers YAML génériques de configuration applicative ne sont pas automatiquement couverts par les règles intégrées de cette commande.
- Le scan analyse les sources présentes dans l’arbre extrait. Il n’évalue ni les valeurs de variables fournies au déploiement, ni les états Terraform, ni les comptes AWS, ni les services actifs. La configuration n’est pas une preuve de déploiement.
- Le bundle utilisé est le bundle intégré à Trivy 0.76.0, établi par le message de repli du journal. Le rapport ne contient pas l’identifiant/version de révision du bundle ni sa date; son âge exact reste inconnu. `--skip-check-update` a empêché de demander sa mise à jour.
- L’image locale n’a pas le même identifiant de configuration que celui associé au rapport initial, malgré les couches communes. Les résultats sont attribués à l’arbre de l’image locale décrit ici.
